# Nuclear Option Map

Standalone map library, separate from the sibling BepInEx mods and server projects. User requested public GitHub source, no npm publishing, and a local-router demo. Work on builtin image maps first, then actual terrain extraction, then satellite/topographic/3D views. Mission overlays are later scope.

Rust owns portable map math and processing; it builds natively and to WASM. TypeScript owns the browser facade and rendering/input adapter. Python/UnityPy is offline extraction tooling, not a browser/runtime dependency. Keep host boundaries explicit; do not pretend a browser renderer runs natively.

Use pnpm (vp where applicable), uv for Python and the installed GNU Rust toolchain. Commit coherent reviewed changes. Preserve other agents' edits; agents have separate file scopes. Public README/API docs contain consumer guidance only. Private investigation evidence belongs in ignored work/.

Never commit game assets, extracted images/meshes, proprietary assemblies, decompiled source or incoming archives. Keep local map outputs in ignored demo/public/maps/ and raw inputs in ignored work/. Do not fake the Nuclear Option map while waiting for assets. Extraction must follow serialized map references and scene transforms; a texture-name guess is not verified mapping. Record exact provenance privately and report partial exports accurately. Do not install mods, launch the game, access servers, publish npm, or change shared infrastructure within this task.

Validate Rust invariants with native tests and execute the WASM build in the browser. Review responsive demo at desktop and phone sizes; passing compilation does not establish visual quality. Inspect full-map water, coastline, cities and airbases at overview and close zoom. Cartographic imagery must provide continuous water and ground coverage; incomplete elevation data stays explicit in the data layer rather than becoming black voids in the visual map. Use spatial raster pyramids for detailed views, retain decoded fallback coverage during pan/zoom/loading, and fade sharper tiles into place. Avoid a giant single image as the detailed map delivery format. Use Claude Sonnet 5.5 as a scoped UI collaborator when available per global guidance.

The requested views have separate visual targets. Satellite means an overhead scene render with recovered terrain/scenery materials, roads, buildings and lighting. A coarse terrain-color texture is not the satellite view. Topographic means contour cartography: readable minor/index contours and elevation labels, restrained land/water fills, roads and building footprints. A strongly shaded hypsometric image is not the topographic default. Support adjustable contour intervals and crisp vector overlays where practical. Inspect representative coastal, urban, airbase and mountain close-ups before accepting a view; metadata/height accuracy alone does not establish map quality.

Satellite browsing must serve precomputed tiles; do not put Blender rendering in the pan/zoom request path. Advertise only complete static levels. Terrain texture enhancement must preserve source geography and be visually checked for GPU texture-size limits and seams before baking. Keep measured terrain/contour data separate from optional display smoothing. For disk use, retain source inputs, extraction provenance and current deliverables, remove superseded generated prototypes after checking their consumers, and disable automatic Blender backup copies in reproducible scene generation.

Offline rendering may share GPU resources with other applications. All render helpers must use render_safety.py: CPU Cycles by default, at most two render threads, CPU compositor, denoising disabled and an exclusive render slot. Explicit GPU jobs require verified total scene memory and time bounds in addition to limits on individual textures, decoded texture memory and output size; the current CLI fails closed without those bounds. Never probe GPU allocation limits by rendering an oversized texture. Do not run unguarded bpy.ops.render.render or multiple GPU workers. CPU and GPU datasets need separate provenance/output paths.
